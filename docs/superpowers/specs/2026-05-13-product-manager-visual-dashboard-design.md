# 产品经理可视化看板设计

## 项目背景

当前项目是一个面向小红书 App Store 评论的 Streamlit 舆情分析工具，已经具备这些能力：

- `app.py` 和 `nlp_analysis.py` 中的本地 NLP 分析。
- 使用 SnowNLP 计算评论情绪指数。
- 使用 TF-IDF 提取好评和差评关键词。
- `ai_analysis.py` 中的 DeepSeek AI 洞察能力。
- Streamlit 页面中的基础图表、评论表格和 AI 文本展示。

下一步改进是：把已经量化出来的数据自动转成产品经理可用的可视化看板。重点不是单纯多画几张图，而是帮助回答产品决策问题：

- 用户现在最不满什么？
- 哪些问题最应该优先解决？
- 好评主要由哪些因素驱动？
- 哪些评论是高风险评论，需要马上关注？
- AI 洞察和本地量化数据是否互相印证？

## 目标

构建一个产品经理视角的自动可视化看板，把评论数据自动转换成决策指标、图表、问题优先级和可行动评论列表。

第一版优先解决“自动找出最该优先处理的问题”。报告生成和评论筛选也会包含，但它们服务于这个核心目标，不单独扩成复杂系统。

## 不做什么

- 不替换现有本地 NLP 和 AI 分析模块。
- 不引入数据库、登录系统或长期历史存储。
- 不做一个只有展示效果、不能辅助决策的装饰性页面。
- 不强依赖 DeepSeek；没有 API Key 时，本地可视化看板也要能正常工作。
- 不做复杂的手动图表配置系统。

## 推荐方案

采用“模块化看板增强”方案：

- 新增 `visual_analysis.py`，专门负责量化指标、问题分类、优先级评分和图表数据准备。
- `app.py` 继续负责 Streamlit 页面布局、筛选控件和图表展示。
- `ai_analysis.py` 继续负责 DeepSeek 配置、请求和结构化 AI 洞察。

这样既符合当前项目规模，也能避免所有逻辑继续堆进 `app.py`。

## 系统结构

```text
上传 CSV
-> app.py 读取并校验数据
-> process_data 增加分词和情绪指数
-> visual_analysis.py 计算本地看板指标
-> ai_analysis.py 可选生成 AI 洞察
-> visual_analysis.py 可融合 AI 严重度到问题优先级
-> app.py 渲染产品经理看板
```

## 文件职责

`app.py`

- 页面布局、文件上传、筛选器、图表、表格和 AI 按钮。
- 调用 `visual_analysis.py` 获取产品指标和图表数据。
- 只在需要 AI 洞察时调用 `ai_analysis.py`。

`visual_analysis.py`

- 计算产品健康指标。
- 按关键词和规则识别问题类型。
- 计算问题优先级分数。
- 生成图表所需的 DataFrame。
- 筛选高风险评论和异常评论。

`ai_analysis.py`

- 保持现有职责：DeepSeek 配置、提示词、接口请求和结果标准化。
- 其中 `pain_points` 的严重度可以作为问题优先级评分的一个输入。

`tests/test_visual_analysis.py`

- 测试本地看板逻辑，不调用 Streamlit，也不调用 DeepSeek。

## 看板结构

### 1. 产品健康概览

顶部展示核心指标：

- 总评论数。
- 平均星级。
- 差评占比。
- 平均情绪指数。
- 高风险评论数。

这些指标要随着筛选条件变化而更新，帮助用户理解当前筛选范围下的产品状态。

### 2. 问题优先级 Top 5

这是整个看板最重要的区域。它不只展示高频词，而是用优先级分数判断最值得先处理的问题。

每个问题包含：

- 问题类型。
- 优先级分数。
- 严重程度标签。
- 相关评论数量。
- 平均评分。
- 平均情绪指数。
- 代表评论。
- 如果有 AI 洞察，则展示处理建议。

第一版问题类型：

- 账号类：封号、禁言、限流、实名、申诉。
- 审核类：审核、违规、举报、笔记、内容规则。
- 客服类：客服、人工客服、反馈、无人处理。
- 体验类：卡顿、闪退、加载、广告、推荐质量。
- 内容类：搜索、推荐、内容质量、社区、种草。
- 其他类：无法匹配到以上类型的评论。

### 3. 评分与情绪诊断

自动生成这些图表：

- 评分分布图。
- 情绪指数分布图。
- 评分 × 情绪散点图。

散点图重点用于发现：

- 高星级但情绪很负面的评论。
- 低星级但情绪中性或正面的评论。
- 无论评分如何都极度负面的评论。

### 4. 关键词对比

并排展示：

- 差评关键词 Top N。
- 好评关键词 Top N。

这样可以解释为什么某些问题被排到高优先级，也保留当前 NLP 分析的透明度。

### 5. 可行动评论池

提供给产品、运营或客服查看的评论表格。

支持筛选：

- 评分范围。
- 情绪指数范围。
- 问题类型。
- 关键词搜索。
- 只看高风险评论。

表格关键字段：

- 评分。
- 情绪指数。
- 问题类型。
- 风险标签。
- 评论内容。

### 6. AI 决策建议

如果配置了 DeepSeek 并生成了 AI 洞察，则展示：

- AI 总结。
- 带严重度的痛点。
- 产品或运营建议。
- 高风险评论。
- 可复制的汇报文案。

AI 区域应靠近“问题优先级 Top 5”，方便对比模型判断和本地量化证据。

## 自动图表清单

只要数据字段满足条件，系统自动生成：

1. 评分分布图。
2. 情绪指数分布图。
3. 评分 × 情绪散点图。
4. 差评关键词 Top N。
5. 好评关键词 Top N。
6. 问题优先级 Top 5 图。
7. 高风险评论表。
8. 如果存在可用时间字段，则额外生成舆情趋势图。

如果缺少某个字段，就跳过对应图表，并在必要时给出简短提示。

## 问题优先级分数

问题优先级不能只看出现次数。第一版评分模型如下：

```text
优先级分数 =
负面评论数量权重 35%
+ 情绪负面程度权重 25%
+ 低评分程度权重 20%
+ AI 严重度权重 15%
+ 风险加分权重 5%
```

各部分含义：

- 负面评论数量：匹配到该问题的低分评论越多，分数越高。
- 情绪负面程度：平均情绪指数越低，分数越高。
- 低评分程度：平均评分越低，分数越高。
- AI 严重度：AI 返回的 `high / medium / low` 会映射成数值；没有 AI 时使用中性默认值。
- 风险加分：极低情绪、极低评分、评分情绪错位等评论会增加分数。

严重程度标签：

- `high`：优先级分数 >= 75。
- `medium`：优先级分数 >= 45 且 < 75。
- `low`：优先级分数 < 45。

这些阈值应集中放在 `visual_analysis.py` 中，方便后续调整。

## 筛选交互

侧边栏增加：

- 评分范围。
- 情绪指数范围。
- 问题类型多选。
- 关键词搜索。
- 只看高风险评论开关。

筛选条件变化后，以下内容同步更新：

- 产品健康概览。
- 图表。
- 问题优先级表。
- 可行动评论池。

原始上传数据保留在内存中，清空筛选后恢复全量视图。

## 异常处理

需要处理：

- 上传空 CSV。
- 缺少必要列 `评分` 和 `内容`。
- 处理前缺少情绪字段。
- 筛选后结果为空。
- 当前筛选范围下没有关键词数据。
- 缺少 DeepSeek API Key。
- AI 返回结果缺少某些字段。

报错提示要简短、明确，并且 AI 失败不能影响本地可视化看板。

## 测试与验证

新增 `visual_analysis.py` 的本地测试：

- 产品健康指标计算正确。
- 已知关键词能正确归类到问题类型。
- 严重账号类或客服类问题的优先级高于轻微问题。
- 评分、情绪、类型、关键词筛选可用。
- 空数据返回安全默认值。
- 可以融合 AI 严重度，但不需要真实 API 调用。

人工验证：

- 使用 `xiaohongshu_reviews.csv` 运行看板。
- 上传后确认图表正常渲染。
- 未配置 `DEEPSEEK_API_KEY` 时，本地看板仍然可用。
- 生成 AI 洞察后，能在问题优先级附近看到 AI 建议。
- 调整筛选条件后，图表和评论表同步更新。

## 实施顺序

1. 创建 `visual_analysis.py`，先实现纯数据函数。
2. 添加指标、分类、评分、筛选相关测试。
3. 在 `app.py` 中接入新模块。
4. 增加产品经理看板布局和图表。
5. 把 AI 严重度融合进问题优先级评分。
6. 运行单元测试和语法检查。
7. 启动 Streamlit，手动检查页面效果。
